# Аудит кода — 17 ноября 2026

Проверена структура всех пакетов, точки чтения файлов и сетевых ответов, запуск процессов,
хранение данных, авторизация, фоновые задачи, рендеринг HTML и существующие тесты.
Углублённая проверка сосредоточена на этих границах; это не доказательство отсутствия
всех ошибок и не полный перебор состояний интерфейса.

## Исправлено

- Общая запись строк JSON экранирует все управляющие символы. Настройки, история манги
  и ранобэ больше не создают нечитаемый JSON при таких символах в данных.
- Изображения EPUB и FB2 сохраняются по SHA-256 содержимого. Одинаковые имена книг
  и похожие пути иллюстраций больше не приводят к перезаписи. EPUB сохраняет `+` в путях.
- FB2 сохраняет короткие секции, текст между секциями и дополнительные тела книги.
- Обнаруженный формат имеет приоритет над ошибочным расширением файла.
- Ограничены чтение текстовых книг, файлов состояния, ответов манги, ранобэ и словаря.
  Сетевые ошибки не включают произвольный текст ответа сервера.
- Сетевые операции ограничивают время передачи тела ответа, а не только ожидания заголовков.
  Незавершённая загрузка удаляет временный файл. Неожиданная HTML-страница отклоняется.
- Завершение TTS вызывает обработчики вне монитора сервиса; ошибка обработчика не ломает остановку.
- Прогресс в режиме свитка учитывает положение прокрутки и ожидание раскладки.
- Название книги в строке состояния не интерпретируется как Swing HTML.
- Старый standalone MasterSolidComplianceTest заменён запускаемым Maven тестом ServiceContractTest.
  Его проверки относятся к отдельным контрактам, а не удостоверяют соблюдение всего SOLID.

## Архитектура и SOLID

| Принцип | Оценка по коду |
| --- | --- |
| SRP | Частично. Выделены загрузчики, хранилища, компоненты карточек и авторизация. ReaderPanel, MangaPanel и RanobePanel всё ещё объединяют построение UI, состояние и координацию сценариев; около 900–1100 строк каждый. |
| OCP | Есть работающие точки расширения BookParser и TtsEngine. Добавление источника манги требует менять ветвления в MangaService. |
| LSP | Есть проверки подстановки парсеров, движков TTS и фабрик моделей ранобэ. Полную корректность всех реализаций они не доказывают. |
| ISP | Каталог разделён на интерфейсы поиска и загрузок. IMangaService и IRanobeService всё ещё объединяют сетевые операции и сохранение состояния. |
| DIP | Часть зависимостей передаётся через конструкторы. Сохраняются зависимости от конкретных хранилищ, глобальных сервисов и SwingUtilities в OnlineCatalogService. |

Используются Strategy, Repository, Facade, Observer и контроль актуальности асинхронных запросов.
Добавлять новые интерфейсы ради количества не нужно. Следующее выделение должно убрать
конкретную обязанность из панели и позволить проверить её без Swing.

## Границы проверки безопасности

OAuth проверяется локальными сценариями PKCE/state, отмены и ошибок, без нового входа
в реальный аккаунт. Ограничения HTML, распаковки, изображений и десериализации покрыты
регрессиями. Полного fuzzing и независимого пентеста не проводилось.
Пользовательские OPDS-каталоги допускают сетевые адреса пользователя; отдельная политика
доверия к адресам иллюстраций из внешних каталогов остаётся направлением усиления защиты.

Проверены [официальные advisories TwelveMonkeys](https://github.com/haraldk/TwelveMonkeys/security/advisories).
В проекте используется WebP 3.15.0, модуль PICT из advisory GHSA-859w-fq5p-6c86
в зависимостях отсутствует. Это не утверждение об отсутствии любых уязвимостей зависимостей.
Доступен [выпуск 3.15.3](https://github.com/haraldk/TwelveMonkeys/releases/tag/twelvemonkeys-3.15.3);
его обновление стоит проверить отдельно на корпусе изображений.
